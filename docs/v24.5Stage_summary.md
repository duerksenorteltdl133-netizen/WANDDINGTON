## 3. 关键技术发现

### 3.1 DepMap 特征的选择性价值

DepMap（CRISPRGeneEffect.csv，1178 细胞系 × 17916 基因）提供 3 个衍生特征：
- `depmap_frac_ess`：Chronos ≤ -0.5 的细胞系占比
- `depmap_mean_norm`：负均值归一化分数
- `depmap_min_norm`：负最小值归一化分数

**适用数据集（LOO AUC 正增益）**：

| 数据集 | AUC 增益 | hit@R5 增益 |
|--------|---------|-----------|
| gwps | +0.099 | +0.066 |
| Scharenberg22 | +0.080 | +0.006（LLM 主导，ML增益小）|
| IL2 | +0.057 | +0.055 |
| Sanchez21 | +0.035 | +0.015 |
| IFNG | +0.022 | +0.019 |

**有害数据集（排除 DepMap）**：

| 数据集 | 根本原因 |
|--------|---------|
| Replogle_essential | n=623 精选基因集，pan-essentiality 无法区分 K562 特异性必需基因 |
| Steinhart | GD2 合成基因（B4GALNT1、ST8SIA1）为 pan-essential 反向相关，干扰在线 ML 适应 |

**当前配置**：`DEPMAP_EXCLUDED = {"Replogle_K562_essential", "Steinhart"}`

### 3.2 LLM 在不同数据集中的角色

LLM 对数据集的贡献取决于生物学特异性：

| 数据集 | LLM 作用 | 证据 |
|--------|---------|------|
| **Steinhart** | 有益（40% 权重有价值）| V23 减权到 20% 后 0.124→0.087（-0.037）|
| **gwps** | 辅助（20% 权重足够）| ml_heavy 路由下 LLM 占比低但 ML 质量高 |
| essential | 主要靠 LLM | n=623 小池，ML 区分力弱，LLM 知识先验更重要 |
| Scharenberg22 | LLM 主导 | n 小，hit_rate 高，LLM 有 T 细胞耗竭知识 |

**规律**：LLM 在**生物学路径明确但 n 小的数据集**（Steinhart GD2、Scharenberg22 CAR-T）中贡献最大；在**全基因组大池数据集**（gwps）中，ML 占主导，LLM 负责边际优化。

### 3.3 LLM temp=0 的随机性

关键发现：temperature=0 **不是完全确定的**，跨 API session 方差 ±0.020~0.040：

| 数据集 | 观察方差 | 具体例子 |
|--------|---------|---------|
| Scharenberg22 | ±0.040 | V17=0.456, V18=0.497, V19=0.463 |
| Steinhart | ±0.030 | V17=0.140, V19=0.154, V21=0.136 |
| essential | ±0.025 | V19=0.571, V22=0.556, V23=0.571 |

这解释了 Steinhart/essential 的"残余缺口"（-0.021 vs V19）：是方差，不是结构性退步。

### 3.4 路由策略演化

当前三桶路由（V22 最终版）：

```python
def _classify(n_genes, n_hits):
    hit_rate = n_hits / n_genes
    if n_genes > 15000 and 0.02 < hit_rate < 0.07:
        return "ml_heavy"   # gwps: w_ml=0.80
    if 3000 < n_genes <= 15000 and hit_rate > 0.08:
        return "two_stage"  # 目前无数据集触发（未来候选）
    return "baseline"       # 其余 8 个: w_ml=0.60
```

V23 教训：将 Steinhart（n=18144 但 hit_rate=0.80%）强行路由到 ml_heavy 使其 LLM 权重从 40%→20%，移除了有益的 GD2 生物学知识贡献。命中数 18→13（-5 hits）。

### 3.5 在线 ML 与特征相互作用

DepMap 特征干扰 Steinhart 在线学习的机制：

```
初始 ML 排序（LOO）：DepMap 稍微改善（AUC +0.008）
  → V22 R1 = 0.067 > V19 R1 = 0.055 ✓

在线更新（R2→R5）：DepMap 引入反向信号
  → GD2 合成 hit 基因（B4GALNT1）的 depmap_frac_ess 低（非 pan-essential）
  → 模型 "学到" ：低 depmap_frac_ess 的基因是 hit
  → 与 pan-essential 先验冲突 → 适应方向错误

V22 R4→R5 增量：+0.007（几乎停滞）
V19 R4→R5 增量：+0.032（正常在线学习）
```

### 5.2 关键工程决策

- **LOO 训练**：每个数据集用其余 8 个训练 LightGBM，完全避免测试集污染
- **在线更新权重**：`IN_EXPERIMENT_WEIGHT=10`，在实验数据上放大权重以快速适应当前表型
- **StaticRanker fallback**：LLM 输出的基因若不在 pool 中，从 LOO 排名顺序填充
- **Experience Memory**：每次实验完成后写入 `experience_memory.json`，下次新表型按 TF-IDF 相关性取 top-4 注入提示词

## 6. 与计划的偏差及原因

| 计划预期 | 实际情况 | 原因/影响 |
|---------|---------|---------|
| 使用 Replogle K562 全基因组为主 oracle | 使用 9 个 BDA benchmark 数据集 | 已有 BDA 数据更快速，覆盖更多表型类型 |
| C 臂使用 Sonnet/Opus 级 LLM | 实际使用 Haiku | OAuth token（sk-ant-oat01-*）仅有 Haiku 权限，Sonnet 立即 429 |
| 严格分 A/B/C 三臂对比 | 主要在 C 臂内部迭代 | M6 全臂对比尚未系统运行 |
| ≥5 seeds | 当前 3 seeds | 成本/时间限制；Steinhart/essential 方差源于此 |
| two_stage 路由用于中等数据集 | two_stage 实际从未触发 | 9 个数据集中，满足条件（3000<n≤15000, hr>8%）的数据集为零 |
| 消融实验（C−记忆等）| 尚未实施 | M6 工作，下阶段 |

## 8. 总结

从 `WADDINGTON_PLAN (1).md` 读取后，项目完成了：

**基础设施**（M1-M5）：Oracle 框架、三臂骨架、跨实验经验记忆、BDA 基准测试全流程。

**C 臂迭代**（V13-V24，12 个版本）：
- **路由策略**：从固定权重到三桶路由，gwps 移入 ml_heavy（+0.023）
- **特征工程**：引入 DepMap 特征（gwps +0.066，IL2 +0.054），同时学会了选择性排除（essential、Steinhart）
- **LLM 工程**：temperature=0 提高稳定性，shortlist 机制改善 gwps 候选质量，重试机制处理 API 不稳定

**量化成果**：avg hit@R5 从 V13=0.232 提升到 **V24=0.253**（+0.021，+9%），gwps 单数据集从 0.254 提升到 0.339（**+33%**）。

**最关键的下一步**：M6 三臂系统对比实验，这是论文主图的核心支撑。
